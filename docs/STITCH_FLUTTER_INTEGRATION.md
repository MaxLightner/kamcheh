# کمچه — ادغام دو رابط در یک مخزن

## وضعیت این ادغام (Frontend merge)

- **سایت دسکتاپ/مرورگر:** خروجی طراحی Google Stitch در پوشه `site/`، شامل صفحه اصلی، گالری، سرمایه‌گذاری و مجله. منوی سایت و لینک‌های داخلی بین این صفحات متصل است.
- **اپلیکیشن نصب‌شدنی اندروید:** همان پروژه Flutter موجود در `lib/` و `android/` بدون تغییر تجربه کاربری.
- **Flutter Web برای آزمایش:** از همان `lib/` ساخته می‌شود و در زیردایرکتوری `/app/` سایت منتشر می‌شود؛ مقصد اصلی برای کاربران دسکتاپ همچنان Stitch است.
- **انتشار:** یک GitHub Actions workflow هر دو رابط را از یک commit ساخته و در یک GitHub Pages artifact منتشر می‌کند.

این ادغام به معنی فعال شدن بک‌اند یا مشترک شدن داده‌های فعلی نیست. در این مرحله هیچ اطلاعاتی بین مرورگر و اپلیکیشن همگام‌سازی نمی‌شود.

## نقشه مسیرها

در GitHub Pages پیش‌فرض (`https://maxlightner.github.io/kamcheh/`):

| مسیر | محتوا |
| --- | --- |
| `/kamcheh/` | وب‌سایت Stitch — صفحه اصلی |
| `/kamcheh/gallery.html` | گالری و متخصصان |
| `/kamcheh/investment.html` | طرح صفحه سرمایه‌گذاری — غیرعملیاتی |
| `/kamcheh/magazine.html` | مجله — محتوای نمایشی |
| `/kamcheh/app/` | Flutter Web (برای آزمایش، نه رابط دسکتاپ پیش‌فرض) |

با اتصال دامنه اختصاصی و انتقال سایت به ریشه دامنه، مقدار `--base-href` در workflow باید از `/kamcheh/app/` به `/app/` تغییر کند. فایل‌های HTML از لینک‌های نسبی استفاده می‌کنند.

## آماده‌سازی بک‌اند در مرحله بعد

- یک پروژه مستقل Supabase برای کمچه بسازید.
- قرارداد داده‌ای مشترک: کاربران/پروفایل‌ها، آگهی خدمات، درخواست کار، پیشنهادها، گفتگوها، نمونه‌کارها و پیوست‌ها. آگهی خدمات و درخواست کار **دو موجودیت مستقل** هستند.
- ورود OTP هر دو کلاینت باید به یک هویت Auth متصل باشد. هویت محلی Flutter فعلاً دمو است؛ هیچ حساب نمایشی نباید به کاربر واقعی تبدیل یا به‌صورت خودکار همگام شود.
- سیاست‌های دسترسی سروری (RLS)، اطلاعات خصوصی و نشانی دقیق، آپلود تصاویر و قراردادها باید پیش از انتشار واقعی پیاده‌سازی و آزمون شوند.
- سایت از قبل جایگاه اتصال Supabase در `site/assets/config.js` را دارد؛ آن فایل اکنون عمداً خالی است. کلید `service_role` یا secret نباید در وب منتشر شود.

## ساخت و تست

```bash
# سایت مستقل از Flutter قابل اجراست:
cd site && python -m http.server 8080
# مرورگر: http://localhost:8080

# اپ از همان پروژه فعلی:
flutter pub get
flutter analyze
flutter test test/kamcheh_test.dart test/stages_14_17_test.dart test/stages_7_13_test.dart test/structure_test.dart test/package2_test.dart test/package3_test.dart
flutter build web --base-href /kamcheh/app/ --no-web-resources-cdn
```

برای انتشار Pages ابتدا GitHub repository Settings → Pages → Source را روی GitHub Actions قرار دهید؛ بدون فعال‌سازی این تنظیم، `configure-pages` با خطای Not Found متوقف می‌شود. نتیجه موفق build در CI به تنهایی نشانه در دسترس بودن وب‌سایت نیست.

بخش‌هایی از طرح Stitch محتوای آزمایشی یا لینک‌هایی بدون پیاده‌سازی هستند. آمار و ادعاهای اعتبارسنجی/امانت‌داری و فرصت‌های سرمایه‌گذاری تا پیش از اتصال بک‌اند و راستی‌آزمایی نباید به‌عنوان سرویس فعال معرفی شوند.
