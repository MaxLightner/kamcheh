# کمچه: فاز اول بک‌اند مشترک

این مرحله هسته **مشترک** برای دو رابط مستقل است: وب‌سایت Stitch در `site/` و نسخه Flutter در `lib/`/`android/`. پروژه Supabase کمچه باید از `menosaz` مستقل باشد؛ ایجاد جدول‌های کمچه داخل دیتابیس میزاتو مجاز نیست.

## معماری

- `auth.users` تنها مرجع شناسه کاربری و شماره موبایل است. هر شماره، یک حساب؛ برای کاربران تازه با تریگر یک ردیف خالی در `public.profiles` ساخته می‌شود. تکمیل پروفایل اجباری نیست.
- هر دو رابط برای مشاهده داده‌ها به `service_listings` و `work_needs` متصل می‌شوند. داده‌های دمو از سرور ارسال یا به حساب واقعی تبدیل نمی‌شوند.
- آگهی خدمات و درخواست کار موجودیت‌های متفاوت‌اند. پروفایل مستقل از آگهی است. ورود OTP و تکمیل پروفایل پیش از ثبت آگهی یا درخواست کار لازم است.
- `work_need_private` فقط برای مالک قابل خواندن است. هیچ نشانی دقیق یا مختصاتی در `work_needs` عمومی ذخیره نمی‌شود.
- `work_bids` و `contact_requests` قابلیت درج و خواندن اولیه دارند؛ پذیرش ارتباط، ایجاد گفتگو، پیشنهادهای منتخب و منطق پرداخت نیازمند تراکنش/RPC سروری در فاز بعد هستند. تا پیش از تکمیل، این امکانات نباید به عنوان جریان همکاری واقعی عرضه شوند.
- `contract_drafts` و `accounting_entries` کاملاً شخصی‌اند. اشتراک حقوقی قرارداد نیازمند جریان تایید جداگانه است.
- RLS روی تمام جداول فعال است؛ هیچ کلید `service_role` در وب یا Flutter قرار نمی‌گیرد.

## مراحل فعال‌سازی

1. از طریق Supabase یک پروژه مستقل با نام Kamcheh در سازمان تاییدشده ایجاد کنید (بعد از اعلام و تایید هزینه).
2. migration `supabase/migrations/20261019_001_core.sql` را با ابزار مهاجرت اعمال کنید. پس از آن Security Advisors را بررسی کنید.
3. برای وب، `site/assets/config.js` را با URL پروژه و کلید **publishable** پر کنید. این کلید عمومی است اما دسترسی داده با RLS محدود می‌شود.
4. برای ساخت APK یا Flutter Web، مقادیر `--dart-define=KAMCHEH_SUPABASE_URL=...` و `--dart-define=KAMCHEH_SUPABASE_PUBLISHABLE_KEY=...` را هنگام build فراهم کنید. بدون آنها اپلیکیشن همچنان دموی سابق را نشان می‌دهد.
5. Supabase Phone Auth به ارائه‌دهنده SMS نیاز دارد؛ تا قبل از تنظیم و تست پیامک ایران، ورود واقعی پیامکی ادعا نشود.
6. با دو حساب حقیقی ساخت پروفایل، ثبت آگهی در سایت و مشاهده در اپ و بالعکس را آزمایش کنید. تست RLS با حساب دیگر و کلید ناشناس ضروری است.

## محدودیت اجرایی فعلی

نحوه نمایش Flutter فقط برای بازار اصلی به API مشترک وصل می‌شود؛ مسیرهای قدیمی پیام، تیم، قرارداد، حسابداری و صفحات دیگر همچنان دموی محلی هستند. مهاجرت آنها به سرور باید مرحله‌ای و با تست مستقل انجام شود. اطلاعات نمونه به داده واقعی کاربر تبدیل نمی‌شود.
